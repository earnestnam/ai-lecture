AI 에이전트 활용 방식 완전 정리

⏱ 30분 중급

챗봇 하나로 다 되던 시대는 끝났어요. 지금은 목적과 복잡도에 따라 사용 방식을 골라야 결과가 달라져요. 4가지 방식의 차이, 설정법, 선택 기준을 한 번에 정리해봐요.

🤔 "AI는 그냥 채팅창 아닌가요?"

처음 AI를 쓸 때는 채팅창 하나로 충분했어요. 질문을 입력하면 답변이 나왔으니까요. 하지만 AI를 실무에 깊게 활용하다 보면 벽에 부딪히는 순간이 옵니다.

"이 분석은 5개 팀 데이터를 동시에 처리해야 하는데..."
"같은 프롬프트를 매번 붙여넣어야 해서 번거롭고..."
"답변이 너무 일반적이라 우리 회사 맥락이 없어..."

이럴 때 필요한 게 사용 방식을 업그레이드하는 거예요. 챗봇 → Project → Sub Agent → Agent Team으로 갈수록 더 전문적이고 복잡한 업무를 처리할 수 있지만, 그만큼 설정 난이도와 토큰 비용도 올라가요.

💡 이 페이지를 읽고 나면 4가지 방식의 차이를 설명할 수 있고, 내 업무에 어떤 방식이 맞는지 스스로 판단할 수 있어요. Claude Code와 Gemini CLI에서 Sub Agent를 직접 설정하는 코드도 포함돼 있어요.

📊 4가지 방식 한눈에 보기

1. 챗봇

Claude.ai, ChatGPT, Gemini 등 일반 채팅창에서 텍스트로 질의응답하는 가장 기본 형태예요.

언제 쓰나요?

한계

🗂️
2. Project / GPTs / Gems

사전에 역할·지침·파일을 등록해두면 매번 설명 없이도 특정 맥락 안에서 답변해요.

언제 쓰나요?

한계

3. Sub Agent

오케스트레이터(지휘자)가 전문 역할의 에이전트에게 업무를 위임해요. 각자의 컨텍스트 창에서 독립적으로 처리하고 결과를 오케스트레이터에게 보고해요.

언제 쓰나요?
병렬 처리, 전문화된 업무 분담, 컨텍스트 분리
한계
에이전트끼리 직접 대화 불가, 오케스트레이터 통해서만
실험 기능 👥
4. Agent Team

팀원 에이전트들이 공유 태스크 목록과 메시지 시스템으로 서로 직접 소통하며 협업해요. 팀장(Team Lead)이 조율하지만 팀원끼리도 직접 대화 가능해요.

언제 쓰나요?
복잡한 탐구, 서로 검증이 필요한 작업, 경쟁 가설 테스트
한계
기본 비활성 상태, 토큰 소비 많음, 아직 제한 있음

🗂️ Project / GPTs / Gems 이란?

Claude의 Project, ChatGPT의 GPTs, Gemini의 Gems는 모두 같은 개념이에요. 대화를 시작하기 전에 AI에게 미리 역할, 지침, 배경 정보를 "등록"해두는 기능이에요.

예를 들어 "우리 회사 HR 담당 어시스턴트"를 만든다면, 회사 복리후생 정책 PDF, 자주 묻는 질문 문서, 답변 형식 지침을 미리 등록해두고, 이후엔 그냥 질문만 하면 돼요.

⚠️ RAG(실시간 검색)와는 다르어요
파일을 업로드하면 AI가 그 내용을 참조하지만, 실시간으로 외부 데이터베이스에서 최신 정보를 가져오는 게 아니에요. 파일이 오래됐다면 직접 업데이트해야 해요. 실시간 연동이 필요하다면 API + 외부 데이터베이스 연결이 필요한 다른 수준의 구조가 필요해요.
도구이름파일 업로드외부 도구 연결
ClaudeProject✅✅ (MCP 서버)
ChatGPTGPTs✅✅ (Actions)
GeminiGems✅제한적

🤖 Sub Agent — 오케스트레이터 + 전문가 팀

Sub Agent는 지휘자(오케스트레이터)가 전문가 에이전트들에게 업무를 위임하는 구조예요. 각 에이전트는 독립된 컨텍스트 창에서 자기 업무만 처리하고 결과를 지휘자에게 보내요. 에이전트끼리는 직접 소통하지 않아요.

오케스트레이터 (지휘자)
↙          ↓          ↘
리서처    분석가    작성자
↘          ↓          ↙
결과물 취합 → 오케스트레이터

Claude Code에서 Sub Agent 설정하기

Claude Code는 .md 파일로 에이전트를 정의해요. 파일 위쪽에 YAML 형식으로 이름, 설명, 사용 모델, 허용 도구를 적고, 그 아래에 에이전트의 역할 지침을 한국어나 영어로 작성하면 돼요.

1 에이전트 정의 파일 만들기 (.md) ▼

프로젝트 폴더 안에 .claude/agents/ 폴더를 만들고, 에이전트 역할 이름으로 .md 파일을 생성해요.

# 폴더 구조
my-project/
└── .claude/
    └── agents/
        ├── researcher.md       ← 리서치 전문 에이전트
        ├── data-analyst.md     ← 데이터 분석 에이전트
        └── writer.md           ← 보고서 작성 에이전트
2 에이전트 파일 내용 작성하기 ▼

파일 상단에 YAML 헤더(프론트매터)로 기본 설정을, 그 아래에 에이전트 역할 지침을 작성해요.

---
name: researcher
description: 리서치가 필요할 때 사용. 특정 주제에 대한 정보 수집,
             사실 확인, 최신 동향 파악 업무를 담당해요.
model: claude-haiku-4-5
tools:
  - WebSearch
  - WebFetch
  - Read
---

당신은 전문 리서처예요. 주어진 주제에 대해 핵심 정보를 빠르게 수집하고,
신뢰할 수 있는 출처 기반으로 요약 보고서를 작성해요.

보고서 형식:
1. 핵심 요약 (3줄 이내)
2. 주요 발견 사항 (불릿 포인트)
3. 출처 목록
💡 description이 핵심이에요
오케스트레이터가 이 description을 보고 "이 작업은 researcher 에이전트에게 맡겨야겠다"고 판단해요. 구체적으로 써야 올바른 에이전트가 선택돼요.
3 실제 사용 — 자연어로 지시하기 ▼

파일을 만들어두면 Claude Code가 자동으로 감지해요. 이후엔 자연어로 요청하면 알아서 적절한 에이전트에게 위임해요.

# Claude Code에서 이렇게 요청하면:
"경쟁사 3곳의 최신 가격 정책을 조사하고, 분석해서,
임원 보고서로 정리해줘"

# Claude가 자동으로:
# 1. researcher 에이전트 → 가격 정보 수집
# 2. data-analyst 에이전트 → 비교 분석
# 3. writer 에이전트 → 보고서 작성
# 4. 오케스트레이터 → 결과 취합 및 최종 전달

Gemini CLI에서 Sub Agent 설정하기

Gemini CLI도 Claude Code와 거의 동일한 방식이에요. 폴더 위치와 파일 경로만 달라요.

1 Gemini CLI 에이전트 파일 위치 ▼ 
# 프로젝트 전용 에이전트 (팀 공유)
my-project/
└── .gemini/
    └── agents/
        └── researcher.md

# 개인 전용 에이전트 (내 PC 전체에 적용)
~/.gemini/agents/researcher.md
2 Gemini CLI 에이전트 파일 형식 ▼

Claude Code와 거의 같은 YAML 프론트매터 형식이에요.

---
name: researcher
description: 리서치 전문 에이전트. 주제 조사, 최신 동향 파악,
             정보 수집 업무를 담당해요.
---

당신은 전문 리서처예요. 요청받은 주제를 깊이 조사하고
핵심 내용을 구조적으로 정리해서 보고해요.

Gemini CLI에서는 @에이전트이름으로 특정 에이전트를 직접 지목할 수도 있어요:

@researcher 최근 1주일간 AI 에이전트 관련 주요 뉴스 정리해줘

👥 Agent Team — 에이전트들의 진짜 팀워크

⚠️ Agent Team은 현재 실험 기능이에요 (Claude Code v2.1.32+)
기본적으로 비활성화되어 있고, 설정에서 직접 켜야 사용할 수 있어요. 세션 복원, 태스크 동기화 등 일부 제한이 있어요. 안정성을 중시한다면 Sub Agent를 먼저 활용해보세요.

Sub Agent와 Agent Team의 가장 큰 차이는 에이전트끼리 직접 소통 가능 여부예요. Sub Agent는 오케스트레이터만 정보를 받아 전달하지만, Agent Team은 팀원들이 서로 메시지를 주고받고 공유 태스크 목록을 보면서 협업해요.

Sub Agent 소통 방식
에이전트A → 오케스트레이터
에이전트B → 오케스트레이터
에이전트C → 오케스트레이터
(에이전트끼리 직접 대화 없음)
Agent Team 소통 방식
팀원A ↔ 팀원B
   ↕        ↕
팀리드 ↔ 팀원C
(공유 태스크 목록 + 메시지)

Agent Team 활성화 및 사용법

1 settings.json에서 실험 기능 활성화 ▼

~/.claude/settings.json 파일에 아래 설정을 추가해요.

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
2 자연어로 팀 구성 요청하기 ▼

설정 후에는 Claude Code에서 자연어로 팀 구성을 요청해요. Claude가 알아서 팀을 구성하고 태스크를 배분해요.

# 예시 1: 서로 다른 관점으로 검토하는 팀
"에이전트 팀을 구성해서 이 신규 서비스 기획안을 검토해줘.
 한 명은 UX/사용자 관점, 한 명은 수익성/비즈니스 관점,
 한 명은 기술 구현 가능성 관점으로 분석하고 서로 의견을 나눠봐."

# 예시 2: 경쟁 가설로 문제를 조사하는 팀
"고객 이탈률이 갑자기 올라간 원인을 조사하는 팀을 만들어줘.
 3명의 팀원이 서로 다른 가설을 가지고 데이터를 보고,
 서로 반박하면서 진짜 원인을 찾아봐."
💡 팀 구성이 가장 효과적인 상황
① 여러 관점의 검토가 필요할 때 (코드 리뷰: 보안 / 성능 / 테스트 커버리지)
② 경쟁하는 가설을 동시에 검증할 때
③ 독립적으로 나눌 수 있는 큰 프로젝트 모듈 작업
3 팀원과 직접 대화하기 (in-process 모드) ▼

터미널 안에서 팀원들이 동시에 돌아가요. Shift+↓로 팀원 간 전환하면서 직접 메시지를 보낼 수 있어요.

Shift+↓다음 팀원으로 전환
Ctrl+T공유 태스크 목록 보기
Esc팀원 작업 중단

🔧 하네스 엔지니어링이란?

AI를 어떻게 쓸지 결정하는 게 도구 선택이라면, 그 도구들을 연결하고 최적화하는 구조를 만드는 게 하네스 엔지니어링(Harness Engineering)이에요.

"하네스(Harness)"는 마차나 기계에서 여러 부품을 연결하는 장치예요. AI에서도 같아요 — 챗봇 한 개보다 여러 에이전트를 엮어서 더 강한 결과를 만드는 구조 설계예요.

📐
설계 (Design)

어떤 에이전트가 몇 개 필요한지, 역할을 어떻게 나눌지, 결과물을 어떤 순서로 처리할지 설계해요.

⚙️
설정 (Config)

CLAUDE.md, 에이전트 .md 파일, settings.json, hooks 등 실제 파일로 구현해요.

📊
최적화 (Optimize)

어떤 에이전트에 어떤 모델을 쓸지, 컨텍스트 창을 어떻게 관리할지, 토큰 비용을 어떻게 줄일지 조정해요.

💡 실무 하네스 예시 — 주간 보고서 자동화

1. 데이터 수집 에이전트 (Haiku 모델, 저비용) → 스프레드시트에서 데이터 읽기
2. 분석 에이전트 (Sonnet 모델, 중간) → 주요 지표 분석, 이상치 탐지
3. 작성 에이전트 (Sonnet 모델) → 경영진용 보고서 초안 작성
4. 검토 에이전트 (Sonnet 모델) → 맞춤법, 일관성, 수치 정확성 교차 검증

→ 오케스트레이터가 전체 순서 관리, 최종 결과물만 사람에게 전달

하네스 엔지니어링 관련 참고 자료

아래는 실제 현업에서 많이 사용하는 멀티에이전트 프레임워크예요. 코드 없이 개념만 살펴봐도 구조를 이해하는 데 도움이 돼요.

프레임워크특징쓰는 곳
CrewAI 역할 기반 팀 구성, 직관적인 설정 Fortune 500 기업 60%+ 사용, 빠른 프로토타이핑에 좋음
LangGraph 그래프 기반 정교한 워크플로 설계 LinkedIn, Uber 등 프로덕션 환경에 강함
AutoGen (Microsoft) 에이전트 간 대화·토론 시뮬레이션 의사결정, 그룹 협의가 필요한 시나리오
