6칸을 그리면 Claude Code가 GAS 코드를 만들어줍니다. 4단계로 첫 자동화를 완성해요.

Claude Code — AI와 짝 프로그래밍

무엇인가

VSCode 안에서 Claude와 대화하면서 코드를 짜는 CLI 도구. 6칸을 설명하면 GAS 코드를 완성해줍니다.

핵심 원칙

  • ✦ 코드부터 시키지 말 것
  • ✦ "데이터 구조 어떻게 잡으면 좋겠어?"부터
  • ✦ 6칸이 명확할수록 코드 품질이 올라감
  • ✦ 한 번에 한 섹션씩 빌드

어떻게 사용하나

  1. 6칸을 텍스트로 정리
  2. Claude Code에게 설명
  3. 생성된 GAS 코드 검토
  4. Google Apps Script에 붙여넣기 → 테스트
프롬프트 예시 
// 이렇게 시작하세요
"6칸 기반으로 GAS 코드 짜줘.
 트리거: 캘린더 시간 기반 (5분마다 체크)
 INPUT: Gemini 회의록 + 캘린더 이벤트 정보
 OUTPUT: 슬랙 DM 발송 (슬랙 마크다운 형식)
 API Key는 Script Properties로 읽어줘.
 헤더명으로 열을 찾는 방식 사용해줘."

6칸 → 코드 → 배포까지 — 4단계

01 6칸 그리기 (종이 or 노션)
코드 전에 설계부터. 6칸이 명확할수록 Claude가 더 정확한 코드를 만들어줍니다. 30분이면 충분합니다.
02 Claude Code에게 설명
6칸 내용을 그대로 텍스트로 붙여넣기. "데이터 구조부터 어떻게 잡으면 좋겠어?" 먼저 물어보세요.
03 GAS 코드 검토 + 수정
생성된 코드를 Claude와 함께 읽으면서 검토. "이 함수 뭐 하는 거야?" 바로 물어보면 됩니다.
04 Apps Script에 배포 + 테스트
코드 붙여넣기 → 권한 설정 → 테스트 실행 → 로그 확인. 슬랙 DM이 오면 완성.

clasp — 코드를 로컬에서 관리하기

무엇인가

clasp(Command Line Apps Script)는 GAS 프로젝트를 로컬 파일로 받아 Claude Code로 편집하고, 다시 Google 서버에 올릴 수 있게 해주는 CLI 도구.

설치 & 로그인 
$ npm install -g @google/clasp
$ clasp login  # Google 계정 인증
$ clasp --version  # 설치 확인
pull
clasp clone [Script ID] 또는 clasp pull
기존 프로젝트 동기화
push
Claude Code로 편집 후 clasp push
GitHub의 git push와 동일 개념
deploy
clasp deploy
Slack이 호출할 수 있는 공개 URL 생성
"Apps Script 에디터에서 직접 작성해도 되지만, clasp + Claude Code 조합이 훨씬 빠릅니다 — 수정-푸시-테스트 사이클이 30초"

API Key 보안 — Script Properties

하드코딩이 위험한 이유

  • ✕ 코드를 공유하거나 clasp로 올리면 Key가 노출
  • ✕ GitHub에 올리면 영구 기록에 남음
  • ✓ Script Properties에 저장하면 코드와 완전 분리

설정 위치

Apps Script 에디터 → 프로젝트 설정(⚙) → 스크립트 속성 → 속성 추가

Script Properties로 Key 읽기 
// 한 번만 설정하면 어디서든 읽기 가능
const props = PropertiesService
  .getScriptProperties();

const claudeKey = props.getProperty('CLAUDE_API_KEY');
const geminiKey = props.getProperty('GEMINI_API_KEY');
const slackToken = props.getProperty('SLACK_BOT_TOKEN');
"Claude Code에게 'API Key는 Script Properties로 읽어줘'라고 지시하면 알아서 이 패턴으로 코드를 작성해줍니다"

슬랙 봇 만들기

01 App 생성
api.slack.com/apps → Create New App → From scratch → 앱 이름 + 워크스페이스 선택
02 Bot Token Scopes 설정
OAuth & Permissions → Bot Token Scopes 추가:
chat:write / channels:read / users:read / im:write
메시지 발송·채널 조회·이메일→슬랙ID 매핑·DM 발송
03 워크스페이스 설치 + Token 복사
Install to Workspace → Bot User OAuth Token 복사
(xoxb-xxxx-xxxx)
04 Script Properties 저장 + 채널 초대
Token을 SLACK_BOT_TOKEN으로 저장
사용할 채널에서 /invite @봇이름 실행
⚠️ 봇 채널 초대를 잊지 마세요

봇은 워크스페이스에 설치해도 채널에 초대하지 않으면 메시지를 보낼 수 없습니다 — 잊지 말고 /invite 하세요.

GAS 배포 URL을 Slack에 연결하기

① GAS 웹앱 배포
A

배포 → 새 배포
(유형: 웹 앱 / 실행 주체: 나 / 액세스: 모든 사용자)

B

배포 URL 복사
(https://script.google.com/macros/s/.../exec)

C

코드 수정 시 재배포 — clasp push 후 반드시 새 버전으로 배포

② Slack에서 연결 방법 3가지

Incoming Webhook 추천

GAS → Slack 단방향 발송. 알림봇에 최적. 가장 빠르게 시작 가능

Slash Commands

/명령어 입력 → Slack이 GAS URL로 POST. 단순하고 명확한 연결

Event Subscriptions

멘션·메시지 등 이벤트 발생 시 GAS URL로 자동 전달. 반응형 봇에 사용

AI에게 시키기 전에 사람이 먼저 정해야 할 것들

01 시트 데이터 구조를 어떻게?

마스터 시트(잘 안 변함) vs 운영 시트(매일 변함) 분리. 위치(A열)로 박지 말고 헤더명으로 찾기.

02 시트 간 데이터를 어떻게 연결?

공통 키 정하기 (이메일·사번·회의ID). 한 시트가 다른 시트를 참조하는 흐름을 그려보기.

03 절차의 순서와 흐름?

트리거 → 데이터 읽기 → 가공 → 저장 → 알림. 분기(IF)가 필요한 지점 미리 결정.

04 동적 처리와 최적화?

매일 1만 건 vs 매주 100건 — 규모에 따라 처리 방식이 다릅니다. 실행 속도·일괄 처리·캐싱을 Claude와 논의.

"AI는 좋은 요리사. 재료 준비는 우리 몫 — 데이터 구조가 제대로면 코드는 Claude에게 맡겨도 됩니다."

미리 알면 첫 주가 절반으로 — 함정 3가지

① 시트 위치를 좌표로 박지 말 것

A2, B3 대신 indexOf로 헤더 동적 탐색 → 열 추가돼도 깨지지 않음

② 권한 범위 미리 점검

Drive·Calendar·Slack 권한은 코드 작성 전에 확인 — 배포 후 권한 오류 가장 많은 원인

③ 로그를 보지 않고 추측하지 말 것

GAS 실행 로그가 모든 답을 갖고 있음 — 추측 전에 로그 먼저
