칸 ① 시작 방식 — 트리거 2종

자동화는 혼자 켜지지 않습니다. 반드시 무언가가 시작을 '깨워야' 합니다. 그 깨우는 방법이 트리거입니다. 크게 두 가지로 나뉩니다.

⏰ 시간 트리거
정해진 시간에 자동 실행

매일 09:00, 매주 월요일, 매월 1일 — GAS 타임 트리거. 사람이 버튼을 누르지 않아도 됩니다.

  • 매일 아침 — 오늘 마감 업무 슬랙 알림
  • 회의 1시간 전 — 참여자에게 리마인드
  • 주간 — 팀 KPI 요약 자동 발송
⚡ 이벤트 트리거
특정 사건이 발생하면 실행

슬랙 멘션, 시트 새 행 추가, 폼 제출, 이메일 수신 — 누군가의 행동이 자동화를 깨웁니다.

  • @봇 멘션 → 즉시 피드백 생성
  • 요약 요청 이모지 → 스레드 분석 시작
  • 신입 입사 시트 추가 → 온보딩 알림 발송

칸 ②③ INPUT과 OUTPUT 생각법

AI가 하는 일은 결국 INPUT을 받아 OUTPUT을 만드는 것입니다. 이 두 칸을 명확하게 정의할수록 AI가 더 정확하게 일합니다.

② INPUT — AI에게 줄 것

📄
텍스트 / 문서 회의록, 슬랙 스레드, 보고서, 이메일 본문
📊
구조화 데이터 Sheets 데이터, 이름·날짜·상태 같은 필드값
🔗
링크 + 맥락 Google Docs 링크, 대화 히스토리, 이전 결과

③ OUTPUT — AI가 돌려줄 것

✍️
구조화된 요약 결정사항, 액션 아이템, 핵심 3줄 요약
💬
피드백 / 판단 5단 피드백, 우선순위 분류, 개선 제안
⚠️
출력 형식을 반드시 명시할 것 슬랙 마크다운으로, JSON으로, 헤더 포함해서 — 형식이 곧 품질입니다
💡 OUTPUT 형식을 반드시 명시하세요

"슬랙 마크다운으로" vs "JSON으로" vs "헤더 없이 텍스트만" — AI는 형식을 명시하지 않으면 알아서 씁니다. 매번 달라지는 출력 형식은 파싱 오류와 재작업을 만듭니다. OUTPUT 형식은 프롬프트의 마지막 줄에 항상 적어두세요.

칸 ④⑤⑥ 나머지 3칸

앞의 3칸이 "무엇을 할 것인가"라면, 나머지 3칸은 "어디에, 어떻게, 무엇과 함께"입니다.

④
커뮤니케이션
"누구에게 어떻게 전달?"
  • DM vs 채널 vs 스레드
  • 누구에게 (개인 or 전체)
  • 멘션 포함 여부
  • 채널 정책 사전 결정 필수
⑤
데이터 관리
"어디에 저장?"
  • Sheets에 기록 (이력 추적)
  • Drive에 파일 저장
  • 저장 안 함 (임시 처리)
  • 민감 정보 처리 정책 확인
⑥
연동 서비스
"어떤 API를 쓰나?"
  • 복잡할수록 이 칸이 두꺼워짐
  • 각 서비스 권한 범위 미리 확인
  • 연동 수 = 자동화의 복잡도 지표
연동 서비스 칸이 두꺼울수록 복잡한 자동화 — 단순 알림봇보다 AI 페르소나봇의 연동 서비스 칸이 훨씬 두꺼운 이유입니다.

6칸 채우는 순서 — 코드 전에 설계부터

6칸은 순서가 있습니다. 처음부터 연동 서비스를 고민하지 마세요. 트리거와 INPUT부터 정의하면 나머지는 자연스럽게 따라옵니다.

1
어떤 반복이 있나? (트리거 + INPUT)

매주 하는 일, 시간이 걸리는 일을 찾아보세요. "무엇이 이 일을 시작하게 만드는가?" — 시간인지, 누군가의 행동인지 먼저 구분합니다.

2
AI가 무엇을 해야 하나? (OUTPUT)

요약? 피드백? 분류? AI가 할 일을 딱 한 가지로 정의하세요. 두 가지 이상이면 자동화를 두 개로 나누는 것이 더 간단합니다.

3
누구에게 어떻게 전달? (커뮤니케이션)

결과를 받는 사람, 채널, 형식을 결정하세요. DM인지 채널인지 먼저 정책 확인 — 의도치 않은 공개 발송은 가장 흔한 실수입니다.

4
기록이 필요한가? (데이터 + 연동)

이력이 필요하면 Sheets 기록 추가. 연동 서비스 목록을 나열하면 6칸 완성. 여기까지 채워지면 Claude Code에 그대로 넘길 준비가 된 겁니다.

6칸이 채워지면 — Claude Code에 그대로 붙여넣기 → GAS 코드 완성
