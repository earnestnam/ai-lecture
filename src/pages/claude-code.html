클로드 코드 — 바이브 코딩 입문

⏱ 30분 중급

터미널 없이 시작하는 바이브 코딩으로 첫 코드 프로젝트를 완성해봐요.

💻 "코딩은 개발자만 하는 거 아닌가요?"

예전에는 그랬어요. 코딩을 하려면 프로그래밍 언어를 배우고, 개발 환경을 설정하고, 수많은 오류와 씨름해야 했죠.

하지만 이제는 달라졌어요. 바이브 코딩(Vibe Coding)은 "어떤 걸 만들고 싶다"는 아이디어를 AI에게 말하면, AI가 코드를 짜주고 실행까지 도와주는 새로운 방식의 개발이에요. 코딩 지식이 없어도 간단한 도구를 직접 만들 수 있습니다.

💡 바이브 코딩이란? "Vibe" + "Coding"의 합성어로, 코드 문법을 몰라도 원하는 것을 대화하듯 설명하면 AI가 코드를 만들어주는 방식을 말해요. 최근 비개발자들 사이에서 급속도로 퍼지고 있는 트렌드예요.

🛠️ Claude Code란?

Claude Code는 Anthropic에서 만든 AI 코딩 도구예요. VS Code라는 개발자용 에디터에 설치하거나, 터미널(명령어 입력창)에서 사용할 수 있는데, 이 강의에서는 가장 쉬운 방법으로 시작해볼게요.

비개발자를 위한 가장 쉬운 시작 방법

직접 코딩 도구를 설치하지 않고도, Claude.ai 웹사이트에서 바로 코딩 관련 도움을 받을 수 있어요. 아래 예시들을 보시면 어떤 것들이 가능한지 감이 오실 거예요.

📋 바이브 코딩으로 만들 수 있는 것들

📊 자동화 스크립트

엑셀 파일을 자동으로 정리하거나, 반복 작업을 자동화하는 스크립트

🌐 간단한 웹페이지

팀 소개 페이지, 이벤트 안내 페이지, 간단한 폼(양식) 페이지

📱 간단한 앱

할 일 목록, 시간 추적, 간단한 계산기, 체크리스트 앱

🔄 데이터 처리

CSV 파일 변환, 여러 파일 합치기, 형식 통일하기

🎯 Step 1. Claude.ai에서 첫 코딩 요청해보기

먼저 Claude.ai 웹사이트에서 아래 예시를 그대로 따라해보세요.

예시 요청 1: 간단한 HTML 페이지 만들기

"팀 소개 웹페이지 HTML 파일을 만들어줘.
- 회사 이름: 우리 팀
- 팀원 소개 섹션 (이름, 역할, 소개 3줄씩)
- 연락처 섹션
- 보라색과 흰색 컬러 테마, 깔끔한 디자인
- 코드를 바로 복사해서 쓸 수 있게 완전한 파일로 줘"

🚀 Step 2. 받은 코드 실제로 사용하기

HTML 파일 실행하기 (코딩 지식 불필요)

  1. Claude가 준 코드를 복사
  2. 메모장(Windows) 또는 텍스트 편집기 열기
  3. 코드 붙여넣기
  4. 파일명을 index.html로 저장
  5. 저장한 파일을 더블클릭 → 크롬 브라우저에서 열림!
💡 오류가 나면? "이 코드를 실행했더니 [오류 메시지]가 나와. 어떻게 고쳐야 해?"라고 Claude에게 그대로 물어보세요. AI가 오류를 읽고 수정 방법을 알려줘요.

🛠️ Step 3. Claude Code 앱 설치하기 (선택 심화)

더 복잡한 프로젝트를 진행하고 싶다면 Claude Code를 직접 설치할 수 있어요. 하지만 이건 선택사항이에요. 대부분의 비개발자분들은 Claude.ai 웹사이트로도 충분해요.

  1. VS Code 설치: Visual Studio Code 공식 사이트에서 다운로드 (무료)
  2. Claude Code 확장 프로그램: VS Code 마켓플레이스에서 "Claude" 검색 후 설치
  3. API 키 설정: Claude.ai에서 API 키 발급 후 설정
  4. 대화하듯 코딩 시작: VS Code 안에서 Claude에게 요청

🧠 Claude Code의 핵심 구성 요소 3가지

Claude Code를 제대로 활용하려면 3가지 핵심 개념을 알아두면 좋아요. 직접 코드로 작성하거나 복잡하게 설정할 필요는 없어요 — Claude에게 자연어로 요청하면 Claude가 알아서 만들어줍니다. 하지만 각각이 어떤 역할을 하는지는 알고 있어야 적절히 활용할 수 있어요.

📋 CLAUDE.md — 프로젝트 기억장치

Claude Code는 대화가 끝나면 이전 내용을 기억하지 못해요. CLAUDE.md는 이 문제를 해결하는 파일이에요. 프로젝트 폴더에 저장해두면 Claude가 새 대화를 시작할 때마다 자동으로 읽어서 "이 프로젝트는 이렇게 작업해야 해"라는 맥락을 항상 유지할 수 있죠.

어디에 만드나요?

🏢 회사 전체 공통

모든 팀원에게 적용되는 공통 규칙을 정의해요

📁 프로젝트별

해당 프로젝트 폴더 안에 저장, 그 프로젝트에만 적용

👤 내 개인 설정

내 컴퓨터의 모든 작업에 적용되는 개인 지시사항

어떤 내용을 넣나요?

  • 이 프로젝트에서 지켜야 할 규칙 ("파일명은 항상 영문 소문자로")
  • 자주 쓰는 작업 흐름이나 명령어
  • Claude에게 항상 알려줘야 하는 배경 정보
  • 답변 스타일 지시사항 ("항상 한국어로, 친근하게")
💡 실무 예시: 마케터가 매주 보고서를 만들 때, CLAUDE.md에 "보고서는 항상 이 형식으로 작성해", "주요 KPI는 CTR, ROAS, CPA야"를 저장해두면 매번 설명할 필요 없이 Claude가 알아서 적용해줘요.

🔌 MCP — 외부 서비스 연결 다리

기본 Claude Code는 내 컴퓨터 파일만 다룰 수 있어요. MCP(Model Context Protocol)는 Claude를 외부 서비스와 연결해주는 확장 기능이에요. GitHub, Slack, Notion 같은 서비스를 Claude Code와 연결하면 "Slack에서 오늘 온 메시지 요약해줘"나 "GitHub 이슈 목록 보여줘" 같은 작업이 가능해져요.

연결 가능한 서비스 예시

🐙
GitHub
코드 저장소 관리
💬
Slack
메시지 읽기·보내기
📝
Notion
문서 읽기·작성
🗄️
데이터베이스
Supabase, PostgreSQL
☁️
Google Drive
파일 접근·관리
💡 어떻게 연결하나요? "GitHub MCP를 설치해줘"라고 Claude에게 말하면 Claude가 설정 파일을 만들고 연결까지 도와줍니다. 직접 설정 파일을 만질 필요가 없어요.

⚡ Skills — 재사용 가능한 워크플로 레시피

Skills는 자주 하는 작업을 레시피처럼 저장해두고 필요할 때 꺼내 쓰는 기능이에요. 예를 들어 "PR 코드리뷰", "API 문서 작성", "주간 보고서 생성" 같은 작업을 한 번 정의해두면 다음에는 간단한 명령어 하나로, 혹은 맥락에 맞게 Claude가 알아서 실행해줘요.

📁 스킬은 어떻게 구성되어 있나요?

별도의 인덱스 파일 없이, 각 스킬은 폴더 하나 + 파일 하나로 구성돼요.

.claude/
  skills/
    weekly-report/    ← 스킬 이름 = 폴더명
      SKILL.md       ← 설명 + 레시피 전부 여기에
    code-review/
      SKILL.md

🏷️ SKILL.md 안에는 뭐가 들어가나요?

파일 맨 위에 name과 description을 정의하고, 그 아래에 작업 단계를 적어요.

---
name: weekly-report
description: 주간 보고서를 KPI 기반으로 자동 생성.
             CTR·ROAS·CPA 요약 포함.
---

1. 이번 주 데이터 수집
2. KPI 항목별 전주 대비 분석
3. 요약 보고서 형식으로 작성
...
💡 스킬명을 몰라도 돼요! Claude는 세션 시작 때 모든 스킬의 description을 읽어둬요. 그래서 "이번 주 보고서 만들어줘"라고 말해도 weekly-report 스킬이 맞겠다고 판단해서 알아서 실행해줘요. description을 잘 쓰는 게 핵심이에요.

⏱️ 언제 무엇이 로드되나요?

세션 시작 시

모든 스킬의 name + description만 컨텍스트에 올라감
→ 가볍게 유지, 성능 부담 최소

스킬 호출 시

해당 스킬의 레시피 본문 전체가 추가됨
→ 세션이 끝날 때까지 유지

CLAUDE.md와 뭐가 다른가요?

구분 CLAUDE.md Skills
언제 로드? 항상 전체 내용이 올라감 description만 → 호출 시 본문 추가
용도 지속적인 지시사항·규칙 특정 작업 단계별 레시피
실행 방법 자동 적용 (항상) /명령어 또는 Claude 자동 매칭
예시 "항상 한국어로 답변해" "주간 보고서 만들어줘" → weekly-report 자동 실행

⚠️ 꼭 필요한 것만 켜두세요 — 컨텍스트 윈도우 관리

Claude의 기억 공간(컨텍스트 윈도우)은 유한해요. MCP와 Skills는 시작할 때 이 공간의 일부를 미리 차지하기 때문에, 불필요하게 많이 연결해두면 실제로 대화하고 작업할 공간이 줄어들어요. 수치로 직접 확인해볼게요.

📊 실측: MCP 없을 때 vs 다수 연결했을 때 (200k 컨텍스트 기준)

🟢 기본 세션 (MCP 없음) 17k / 200k 사용 (8.5%)
System prompt 3.2k System tools 11.6k Memory 0.7k Autocompact ~13k 여유 공간 183k (91.6%)
🔴 MCP 다수 연결 세션 101k / 200k 사용 (51%)
System prompt 3.1k System tools 19.8k ⚠️ MCP tools 26.5k Agents 2.8k Memory 4k Autocompact ~45k 여유 공간 99k (49.4%)
MCP 연결만으로 여유 공간이 183k → 99k로 절반 가까이 줄었어요. 대화가 길어질수록 이 차이가 고스란히 응답 품질 저하로 이어져요.

각 영역이 차지하는 공간

영역 내용 일반 규모
System prompt Claude의 행동 지침, 역할 정의 2~4k
System tools 기본 내장 도구 정의 (파일읽기, bash, 검색 등) 10~20k
MCP tools 연결된 MCP 서버의 툴 정의 — 서버 수에 비례 0~30k+
Agents / Skills 서브에이전트 정의 + Skills 메타데이터 0.1~3k
Memory files CLAUDE.md · 호출된 SKILL.md 본문 0.3~10k
Messages 대화 히스토리 — 대화할수록 급증 0 → 수십k
Autocompact buffer 자동 압축용 예비 공간 — 줄이기 불가 ~13~45k

📌 핵심 차이: MCP는 연결하는 순간부터 도구 전체 정의가 항상 올라가지만, Skills는 name + description(메타데이터)만 올라가고 실제 레시피 본문은 호출할 때만 로드돼요. MCP 서버 1개 평균 600~1,000 토큰 소비(15개 기준 약 10k)인 반면, Skills는 스킬 1개당 description 250자 수준으로 훨씬 가볍게 관리돼요.
⚠️ 실천 가이드: 대화 시작 전부터 50%가 사라지지 않으려면
  • 지금 이 작업에 실제로 쓸 MCP만 연결하고 나머지는 비활성화
  • 자주 쓰는 작업 패턴은 MCP 대신 Skills로 전환하면 컨텍스트 부담을 줄일 수 있어요
  • 스킬은 32개 이하로 유지 — 그 이상이면 description이 잘려 자동 매칭 정확도가 떨어져요

💡 바이브 코딩 성공 팁

  • 작게 시작하세요: 처음에는 간단한 것 하나부터. 욕심내서 복잡한 걸 만들려다 막히면 포기하게 돼요
  • 원하는 걸 구체적으로 설명하세요: "앱 만들어줘"보다 "이런 기능을 하는 앱 만들어줘"가 훨씬 좋아요
  • 오류를 두려워하지 마세요: 오류 메시지가 나오면 그대로 Claude에게 보내면 돼요
  • 단계적으로 요청하세요: 한 번에 모든 기능을 요청하기보다 기본 → 추가 기능 순서로

📌 핵심 정리 — Claude Code 3가지 구성 요소

  • CLAUDE.md: 세션이 끝나도 사라지지 않는 프로젝트 기억장치. 지시사항·규칙·배경 정보를 저장하면 Claude가 매번 자동으로 읽어요
  • MCP: Claude와 외부 서비스(GitHub, Slack, Notion 등)를 연결하는 확장 기능. 연결 즉시 컨텍스트 공간 차지 — 필요한 것만 연결하세요
  • Skills: 자주 쓰는 작업 레시피. description만 항상 로드되고 본문은 호출 시에만 로드 — MCP보다 컨텍스트 효율이 높아요
